# Эталоны (golden)

Зафиксированные ожидаемые результаты: входы и ответы, с которыми тесты сверяют программу (docs/PLAN.md §5.2).
Один файл — одна функция или один сценарий: разбор имён (anitomy, номер серии, названия), команды ffmpeg
(HLS, аудио), ответы Shikimori, шрифты, и операции целиком (`operation_scenarios`, `rename_scenarios`,
`hls_scenarios`, `mka_scenarios`, `ass_fonts_scenarios`).

Эталоны обновляются вместе с поведением программы — руками, только при осознанном изменении поведения:
в том же PR, что и код, с пояснением, почему ответ стал другим. Тест упал, а поведение менять не собирались, —
ошибка в коде, а не в эталоне.

Реальный вывод ffprobe / ffmpeg / mkvmerge по сгенерированным файлам, на который ссылаются часть случаев, —
в `../Fixtures/media/`.

## Формат

```json
{
  "function": "anitomy_parse",   // совпадает с именем файла без .json
  "description": "…",
  "fixtures": { … },             // есть не у всех: общие входы, на которые ссылаются случаи (объект)
  "cases": [
    {"input": …, "output": …},
    {"input": …, "error": "ValueError"}   // вместо ответа ожидается ошибка
  ]
}
```

У каждого случая ровно одно из `output` / `error`; `cases` не пустой (это проверяет `GoldenFilesTests`).
`error` — вид ошибки: `ValueError` — неверный ввод (в .NET — `FormatException`, `OverflowException`,
`ArgumentOutOfRangeException`), `KeyError`, `IndexError`; соответствие — `GoldenAssert.ErrorName`.

У части случаев есть дополнительные поля: `commands` — какие команды ffprobe/ffmpeg ожидаются,
`calls` — команды проходов подбора CQ с размерами выходных файлов (тест их «проигрывает»),
`api_paths` — запросы к API Shikimori, `layout` — раскладка дорожек.

Пути в эталонах HLS даны для `"platform": "windows"` (как у пользователя: пути с `\`, сегменты HLS с `/`;
на Linux сверяется через `PathStyle.Windows`) и для `"posix"`.

## Что учитывать при сравнении

- Дробные числа (CQ, битрейты) сравнивать с относительным допуском ~1e-9 (`relativeTolerance` в `GoldenAssert.All`):
  `log` в разных библиотеках C может отличаться на последний бит. Средний битрейт — сумма с компенсацией
  (алгоритм Ноймайера, `TextUtils.Sum`).
- Регистр — `TextUtils.CaseFold` / `TextUtils.Lower`, а не `ToLowerInvariant()`: `CaseFold` — свёртка регистра
  Unicode (`ß` → `ss`), проверена для всех символов (эталон `str_casing`).
- `\w`, `\s`, `\d` в регулярках — по правилам `TextUtils`: `\w` = буквы + цифры + `_` (без диакритических знаков,
  в отличие от `\w` в .NET); `\s` — ещё и разделители `\x1c–\x1f`; `\d` — любые десятичные цифры Unicode,
  «０３» → 3 (`TextUtils.ParseInt`).
- Запрос к Shikimori не кодирует `/` (`ShikimoriClient.Quote`; `Uri.EscapeDataString` кодирует).
- Порядок сортировки — по кодам символов; сортировка стабильная.
- Форматирование `%.2f`/`%.3f` — с инвариантной культурой.

Расхождение с эталоном допустимо только осознанно: случай помечается в тесте с причиной (`knownDifferences`
в `GoldenAssert.All`); помеченный случай обязан расходиться — совпал, значит пометку надо убрать.
